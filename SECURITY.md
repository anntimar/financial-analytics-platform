# Política de segurança

## Relato de vulnerabilidades

Não abra um issue público com credenciais, dados financeiros ou detalhes que facilitem a exploração de uma vulnerabilidade. Entre em contato com o mantenedor por um canal privado do perfil do GitHub e inclua:

- componente e versão afetados;
- passos mínimos para reprodução;
- impacto observado ou potencial;
- sugestão de correção, se disponível.

## Escopo

A versão mais recente da branch `master` recebe correções de segurança. O projeto usa somente dados sintéticos e não deve receber dados pessoais ou empresariais reais.

Segredos de produção, tokens e arquivos `.env` nunca devem ser enviados ao repositório.
